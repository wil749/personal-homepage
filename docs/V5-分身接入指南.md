# V5 个人分身 · 接入与维护指南

> 适用于 `outputs/wyw个人主页-V5.0.html`（发布后为仓库根目录 `index.html`）。
> 分身当前是**纯本地知识库**：不调用任何模型、不发请求、刷新即清空（可选本机保留）。

---

## 1. 文件与加载关系

| 文件 | 作用 |
| --- | --- |
| `outputs/wyw个人主页-V5.0.html` | 页面本体，内含匹配器与聊天 UI 逻辑 |
| `outputs/data/persona.js` | 分身知识库（`window.WIL_PERSONA`） |
| `data/persona.js` | 发布时由 `scripts/publish.ps1` 复制到根目录 |

HTML 在 `<head>` 后、内联脚本前加载知识库：

```html
<script src="data/persona.js"></script>
```

**改内容只改 `outputs/data/persona.js`**，然后跑 `scripts/publish.ps1` 同步到根目录。
直接改根目录 `data/persona.js` 会在下次发布时被覆盖。

## 2. 知识库结构

```js
window.WIL_PERSONA = {
  version: "5.0",
  updated: "2026-11",

  style: {
    catchphrases: ["我觉得", "我认为", "可能"],   // 口头禅，写答案时自然带上
    avoid: [ ... ],                              // 隐私关键词，命中即拦截
    boundary: { zh: "...", en: "..." }           // 拦截时的统一回复
  },

  smalltalk: {                                   // 寒暄与自我介绍
    hello: { zh, en },
    thanks: { zh, en },
    bye: { zh, en },
    about: { zh, en },
    can: { zh, en }
  },

  faq: [                                         // 固定问答（精确优先）
    {
      id: "bci",
      kw: ["脑机接口", "bci", "研究", ...],       // 命中关键词（子串匹配）
      zh: { q: "代表问题", a: "答案" },
      en: { q: "...", a: "..." }
    },
    // ... 共 10 条：bci / paint / music / daily / school / project / contact / twin / study / balance
  ],

  topics: [                                      // 话题（多答案轮换）
    {
      id: "paint",
      kw: ["绘画", "画画", ...],
      zh: { answers: ["答案A", "答案B", ...] },   // 同一话题多次提问会轮换
      en: { answers: [...] }
    },
    // ... 共 8 条：paint / music / daily / dance / photo / recommend / future / habit
  ]
};
```

### 字段规则

- **中英必须成对**：切换语言时整段替换，缺一个字段会退化为中文。
- **`kw` 是子串匹配**：`"研究"` 能命中「你最近在研究什么」；太短的词（如「的」）会误伤，不要加。
- **`faq` 优先于 `topics`**：同一个词两边都写时，`faq` 先命中。
- **`topics` 支持多答案**：`answers` 数组按顺序轮换，避免每次回答一模一样。

---

## 3. 匹配器工作顺序

`twinAnswer(input)` 依次判断，命中即返回：

1. **隐私边界**（`style.avoid`）→ 返回 `style.boundary`
2. **空输入** → 兜底文案
3. **寒暄**（问候 / 谢谢 / 再见 / 你是谁 / 你会什么）
4. **追问**（「那……呢」「还有呢」）→ 追问上一个话题
5. **FAQ 打分**（关键词命中数，≥1 即命中）
6. **话题打分**（同上，多答案轮换）
7. **兜底** + 推荐 3 个常见问题

> 新增内容时注意：如果关键词太泛（如「做」），会抢在更精确的主题前面命中。

---

## 4. 隐私边界（重要）

`style.avoid` 里的词一旦出现在问题中，**直接返回 `boundary`，不展开、不猜测**。当前包含：

- 成绩类：成绩 / 分数 / 绩点 / 排名
- 住址类：住址 / 住哪 / 家住 / 宿舍 / 门牌 / 小区
- 身份类：身份证 / 手机号 / 电话
- 家庭感情：父母 / 家里 / 恋爱 / 感情 / 女朋友 / 男朋友

**新增隐私词只需往 `avoid` 数组里加**，中英各一份。修改 `boundary` 可统一改口吻。

⚠️ 不要在 `faq` / `topics` 里写任何与 `avoid` 冲突的具体信息——匹配器虽然会拦截，但答案文本一旦被导出就不会再受控。

## 5. 运行时行为

| 项目 | 说明 |
| --- | --- |
| 默认状态 | 仅内存，刷新清空 |
| 「在本机保留」 | 写入 `localStorage`，键名 `wil_twin_retain_v1` |
| 聊天记录键名 | `wil_twin_log_v1`（最多保留 60 条） |
| 导出 | 生成 `wil-twin-YYYYMMDD-HHmm.txt` |
| 输入上限 | 200 字（`twinCount` 显示剩余字数） |
| 打字机 | 逐字显示，按长度自适应；用户追问会先补完上一句再排队 |
| 队列 | 打字中连续发问最多排队 3 条，按顺序回答，不丢消息 |

## 6. 已接入：智谱 GLM-4-Flash（Supabase Edge Function）

### 6.1 架构与地址

```
访客浏览器
   └─ twinAsk()  ──POST──▶  Supabase Edge Function  ──▶  智谱 GLM-4-Flash
                              (slug: clever-task)
                                  │
                                  └─ 失败/超时 ──▶ 回落本地 twinAnswer()
```

| 项目 | 值 |
| --- | --- |
| Supabase 项目 | `bafmpqiesnsyhtnqfohj` |
| 函数端点 | `https://bafmpqiesnsyhtnqfohj.supabase.co/functions/v1/clever-task` |
| 函数 slug | **`clever-task`**（网页编辑器自动生成，不是 `chat`） |
| 本地源码 | `supabase/functions/chat/index.ts`（目录名与远端 slug 不同，别混淆） |
| 服务端 Secret | `ZHIPU_API_KEY` |
| 模型 | `glm-4-flash` |
| 前端 key | `sb_publishable_...`（publishable 格式） |

### 6.2 请求格式

```http
POST /functions/v1/clever-task
apikey: sb_publishable_xxx
Content-Type: application/json

{ "message": "...", "lang": "zh", "history": [{ "role": "user", "content": "..." }] }
```

返回 `{ "reply": "...", "model": "glm-4-flash" }`，隐私命中时返回 `{ "reply": "...", "guard": "boundary" }`。

### 6.3 三条硬约束

1. **JWT 验证必须关闭** —— publishable key 不是 JWT，开着验证会一直 401。位置：函数详情 → Settings → Enforce JWT verification。
2. **请求头只带 `apikey`，不要带 `Authorization`** —— 带 `Bearer sb_publishable_...` 会被网关拒绝。
3. **`ZHIPU_API_KEY` 只存 Supabase Secret**，永远不要写进前端或提交到仓库。

### 6.4 隐私是双保险

| 层 | 位置 | 作用 |
| --- | --- | --- |
| 前端 | `twinLocalOnly()`（index.html） | 隐私词 / 寒暄本地秒答，**请求根本不发出** |
| 服务端 | `AVOID` 数组（index.ts） | 请求到达后再次拦截，**不转发给智谱** |

改隐私词要**两处同步**：`outputs/data/persona.js` 的 `style.avoid` 和 `supabase/functions/chat/index.ts` 的 `AVOID`。

### 6.5 降级策略

- 请求超时 18 秒或返回非 2xx → 自动回落本地 `twinAnswer()`
- 连续失败 2 次 → 本次会话不再尝试远端（`TWIN.remoteDown`），清空对话后重置
- 手动强制本地：URL 加 `?llm=0`

### 6.6 改完函数后如何重新部署

在 Supabase 控制台 → Edge Functions → 选中 `clever-task` → 编辑代码 → **Deploy**。
部署后回到 Settings 确认 **Enforce JWT verification 仍为关闭**（有时会重置）。

> 用 CLI 部署需要 Access Token 带 `edge_functions_write` 权限；网页部署不需要 token，更省事。

### 6.7 换模型 / 换供应商

`supabase/functions/chat/index.ts` 顶部两个常量：

```ts
const ENDPOINT = "https://open.bigmodel.cn/api/paas/v4/chat/completions";
const MODEL = "glm-4-flash";
```

智谱用的是 OpenAI 兼容格式，换 DeepSeek 只需把 ENDPOINT 改为 `https://api.deepseek.com/chat/completions`、MODEL 改为 `deepseek-chat`，再把 Secret 换成 `DEEPSEEK_API_KEY`（同步改 `Deno.env.get(...)`）。

## 7. 预览与调试参数

在文件 URL 后追加：

| 参数 | 作用 |
| --- | --- |
| `?noopening=1` | 跳过开场动画，直接进正文 |
| `?reveal=1` | 强制显示所有滚动揭示元素（截图用） |
| `?compact=1` | 取消封面 `100svh`，便于整页截图 |
| `?only=twin` | 只显示分身区（移动端单独检查） |
| `?selftest=1` | 自动跑一轮「连续追问」并把结果写入隐藏节点（开发自检） |
| `?diag=1` | 输出横向溢出元素清单（布局诊断） |
| `?llm=0` | 强制本地知识库，不调用模型（离线 / 对比用） |

这些参数只在手动加 query 时生效，不影响正常访客。

## 8. 发布流程

```powershell
# 1. 改 outputs/ 里的源文件（页面或知识库）
# 2. 同步到仓库根目录
powershell -ExecutionPolicy Bypass -File ".\scripts\publish.ps1"
# 3. 提交并推送
git add -A
git commit -m "V5: 分身模块上线"
git push
```

`publish.ps1` 会：

- `wyw个人主页-V5.0.html` → `index.html`
- `outputs\images` → `images\`
- `outputs\data` → `data\`（**V5 新增，缺了分身会加载失败**）
