> 输出物：`outputs/wyw个人主页-V5.0.html`（单文件、离线自包含，延续 V1→V4 的发布形态），副本再合并到根 `index.html` 发布到 GitHub Pages。

## 一、目标与核心判断

| 项 | 判断 |
| --- | --- |
| 风格基调 | **局部纸页化**：只把「分身」做成一本夹在海报档案里的旧日记（羊皮纸跨页）；其他板块保留 V4 黑红。红黑继续做印章 / 书签 / 装订色，确保"同一套视觉语言"。 |

## 二、视觉方向（设计语言）

### 1. 色板（与 V4 红黑统一，仅材质化）

```
--paper       #ECE0C4   主纸面（米黄羊皮纸）
--paper-deep  #D9C9A3   阴影/折痕
--paper-edge  #C2AE83   暗角/装订线
--ink         #1C1A17   墨色（替换原 #000）
--ink-fade    #3A342B   褪色墨
--red         #8E2B25   火漆/印章（替换 V4 海报红，呼应但更"古旧"）
--red-deep    #5E1A16
--brass       #A9884E   装订扣/章环
--pencil      #6B6358   铅笔批注
```

> 纸色变量**只作用于「分身」章节**，不替换全站。V4 的 `--ink #000` / `--red #a80d18` 继续作为全站主色；分身章节内用 `--red #8E2B25` 做火漆，与海报红同源但更"旧"——这是两个风格能统一的关键：**同一套红黑，换一种材质**。

### 2. 材质（纯 CSS 生成，零外链）

- **纸面纹理**：多层 `radial-gradient` + `linear-gradient` 模拟纤维；SVG `feTurbulence` 噪点叠 `mix-blend-mode:multiply`，不透明度 0.18–0.32。
- **暗角 + 折痕**：`box-shadow inset` + 两条斜向半透明 `linear-gradient`。
- **装订线**：左侧 0.5rem 的竖向缝线（`repeating-linear-gradient` + 虚线点），中间两个"装订孔"。
- **便签 / 纸胶带**：黄色便利贴（轻微旋转 2–4°、`drop-shadow`），半透蒙版胶带（`rgba` + 噪点）。
- **火漆印章**：纯 CSS 圆形渐变 + 缺口 + 字母"W"，点击发送时盖上。
- **手写批注**：用 `transform: rotate(-1.5deg)` + 略带透明感的墨色 + 衬线斜体回退。

### 3. 字体（优先系统字体，保持离线）

```
正文：Source Han Serif SC / Noto Serif SC / Songti SC / SimSun（已配置）
标题：同上 + 加重
手写批注：Segoe Print / Bradley Hand / "Caveat"（CDN 备用，离线时回落系统）
打字机：Consolas / Menlo / Courier（英文小段）
```

> 若希望 100% 离线可控，把 `Caveat` 子集化后放进 `outputs/fonts/`，体积约 30–60KB。
> 第一版用系统字体回退，第二版再补字库。

### 4. 动效（统一 `--ease`，遵守 `prefers-reduced-motion`）

- 消息进入：纸张滑入 + 墨迹渐显（`opacity` + `translateY` + `clip-path`）。
- 打字机：每 18–28ms 输出一个字符，标点稍停顿。
- 思考态：纸页轻轻抬起 + 三个墨点跳动。
- 印章：发送瞬间盖下，`scale(1.3)→1` + 一次反弹。

## 三、信息架构与板块

### 1. 顶部导航（增加一项）
`关于 / 兴趣 / 项目 / 问答 / 联系方式 / 留言` → **关于 / 兴趣 / 项目 / 分身 / 联系方式 / 留言**（"问答"改名为"分身"）。

### 2. 封面（V4 保留红色老爷车版式 + 新增"翻页"动作）
- 主标题下方新增按钮：`和我的分身聊聊 →`（跳到 `#twin`）。
- 副标题加手写批注："— 这本日记里，也住着一个我"。

### 3. 分身 · TWIN（核心新板块，替代原 ASK）

**布局**：跨页日记本（左页 + 右页），桌面端两栏，移动端折叠为上下两页。

| 左页（身份页） | 右页（对话页） |
| --- | --- |
| 人物立绘（便签 / 拍立得贴入，胶带斜贴） | 顶部状态条：头像 + 「分身 · WIL」+ 在线状态灯 |
| 手写便签："这是 Wil 在纸上的分身" | 横线纸面聊天区（`repeating-linear-gradient` 横线） |
| 三条「档案」摘要卡：脑机接口 / 舞蹈&绘画 / 城市观察 | 用户消息：右对齐，墨色便签 |
| 火漆印章：「CONFIDENTIAL · 仅你可见」 | 分身消息：左对齐，墨黑纸条，左边 3px 火漆红 |
| 快捷提问（4 个原问答转成的书签条） | 输入区：横线 input + 火漆"寄出"按钮 + 字数提示 |

**交互细节**：
- 输入框 placeholder：「在这里写一句话，按 ⏎ 寄出」
- Enter 发送 / Shift+Enter 换行 / 发送中按钮变印章动画
- 消息时间戳：像印章小字（`opacity:.5; font-size:.62rem`）
- 工具条：`清空这一页`、`导出 .txt`、开关 `在本机保留对话`（默认关，刷新即清空）
- 移动端：左页折叠为顶部 header（立绘缩小成 96px 圆形 + 名字）

### 4. 与 V4 黑红的衔接（关键设计）

「分身」章节用红黑（V4 主色）作为**章节背景**，**羊皮纸跨页漂浮在红黑底色上**——而不是反过来。这样既保留视觉冲击，又解决"两种风格割裂"的问题：

```
┌─ V4 黑底 ─────────────────────────┐
│                                   │
│   ╔═══════════════════════════╗   │  ← 红黑背景里的羊皮纸跨页
│   ║  左页(身份)  │  右页(对话) ║   │     边缘用撕纸 SVG + 胶带斜贴
│   ╚═══════════════════════════╝   │
│                                   │
│   火漆印章 / 邮戳 / 装订线（红黑） │  ← V4 红黑继续做装订元素
└───────────────────────────────────┘
```

- **进入过渡**：从上一板块下滑到分身时，背景从黑 → 暗红 → 黑 + 中间夹着的纸面浮现（`scroll-timeline` 或简单 fade）。
- **章节标题**：复用 V4 `band band--black`，但加一行手写体副标"— 翻到夹在档案里的那本小册子"。
- **章节装饰**：上下各一条撕纸 SVG 边缘线 + 两个胶带角，让"纸"看起来是从背景里撕出来的。
- **保留 V4 红黑位置**：cover / 联系 / 留言板的红黑都不动，只让"分身"成为黑红档案里夹着的一本旧册子。
- **颜色映射**：V4 `--red #a80d18` → 分身章节 `--red-deep #5E1A16` 做火漆；V4 `--ink #000` → 分身章节 `--ink #1C1A17` 做墨色。**色相不变，明度降一档**——这就是"同一套视觉语言，换一种材质"的具体做法。

### 5. 现有 ASK 板块的处理
原「问答 · ASK」（4 个固定问答）整体替换为「分身 · TWIN」；原 4 个问答文案进入分身章节作为**默认快捷提问书签**和知识库 FAQ，不丢失任何 V4 内容。

## 四、个人分身 · AI 技术方案

### 1. 知识库（决定回答质量）

新建 `outputs/data/persona.js`（约 6–10KB），结构：

```js
window.WIL_PERSONA = {
  meta: { name:"王悦为", en:"Wil", role:"...大...", lang_bilingual:true },
  identity: { born:"2008-04-23", school:"...", major:"..." },
  interests: [ {k:"绘画",v:"..."}, {k:"舞蹈",v:"..."}, ... ],
  music:   { genres:[...], artists:[...] },
  projects:[ {title, role, status} ],
  skills:  [...],
  facts:   { hometown:"成都", based:"深圳", ... },
  style:   { tone:"温和、自嘲、文艺", avoid:["政治、宗教、他人八卦","代替本人做承诺"] },
  faq:     [ /* V4 的 4 个问答 + 5–8 条补充 */ ],
  closing: "我不知道的事我会说不知道，可以把你介绍到留言板。"
};
```

加载：`<script src="data/persona.js">`，与 `index.html` 同源，双击可开。

### 2. 对话链路（V5 主路径：本地匹配；LLM 预留）

```
访客输入
  └─ 1) 本地知识库匹配器（V5 主路径）
        ├─ 预处理：小写化 / 去标点 / 简繁归一 / 中英检测
        ├─ 意图分类：
        │     • 寒暄（你好/hi/在吗/谢谢/再见）
        │     • FAQ 命中（每条配 5–10 个关键词 + 同义句）
        │     • 实体查询（学校/专业/家乡/兴趣/音乐/项目/联系方式）
        │     • 越界（手机号/微信号/政治/医疗/法务）→ 拒答
        │     • 模糊（关键词命中 < 阈值）→ 兜底 + 推荐 3 个问题
        ├─ 多轮上下文：保留最近 4 轮用户问题，做指代消解
        │     "那音乐呢" → 继承上一主题
        ├─ 回答拼接：从 persona 字段抽取 + 3 套随机句式（避免复读）
        ├─ 语言：检测中英 → 选 zh/en 字段；混合时按主体
        └─ 输出：打字机逐字渲染，标点停 80ms
  └─ 2) [预留] LLM 网关（如未来配置 SUPABASE_URL/chat）
        └─ Edge Function 拼 system prompt + 最近 6 轮
              → OpenAI 兼容 /chat/completions（流式 SSE）
              → 未配置时不显示，匹配器自动顶上
```

**关键约束**：
- **永远能聊**：即使 JS 报错、persona.js 加载失败、网络断开，都要给出兜底文案（"我还在写，等下次再聊？"），**绝不允许白屏**。
- **零依赖**：匹配器纯本地正则 + 字段查找，< 8KB，无 fetch。
- **可升级**：匹配器命中失败时（未来指标）再接 LLM。

### 3. 聊天记录策略

| 项 | 策略 |
| --- | --- |
| 默认存储 | 内存数组（`window.__twinLog`），刷新即清空 |
| 持久化 | 工具栏开关"在本机保留对话"，开启后写 `localStorage["wil_twin_log_v1"]`，最多 50 条 |
| 导出 | `导出对话 .txt`，文件名 `wil-twin-{YYYYMMDD-HHmm}.txt`，含时间戳与角色 |
| 不收集 | 不发到 Supabase、不打 cookie、不发任何分析请求 |

### 4. [预留] 后端：Supabase Edge Function（未来升级）

不在 V5 范围，但保留接入位：
- 文件：`supabase/functions/chat/index.ts`
- 环境变量：`LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL`
- 请求体：`{ messages: [{role,content},...], lang }`
- 响应：`text/event-stream`（逐字流式）
- 安全：Origin 白名单、单 IP 限流（60 次/小时）、消息 ≤ 4KB、单会话 ≤ 8 轮上下文、prompt 注入防御、错误兜底文案
- 前端：`window.WIL_CHAT = { enabled:false }`，未配置时本地匹配器自动接管
- 启用步骤写在 `docs/V5-分身接入指南.md`，留给后续 PR

### 5. 隐私与安全

- V5 不引入任何外部 LLM 调用，**仓库里不会有任何 key**。
- 不收集访客身份（不强制登录、不写 cookie）。
- 聊天记录默认内存态；开关开启后才写 localStorage，可一键清空。
- 不把访客输入写进 Supabase 留言表（留言表已存在独立流程，互不干扰）。
- 匹配器内置拒答：隐私字段（手机/微信号除非公开字段）、政治/医疗/法务。
- 仓库推送前用 `push-to-github` skill 检查敏感词。

### 6. [预留] LLM 提示词模板（未来升级时用）

```
你是「王悦为 / Wil」在个人主页上的纸面分身。回答时：
- 用第一人称"我"，语气温和、自嘲、带文艺感；
- 不知道就说不知道，引导到留言板；
- 单条 ≤ 220 字，分段自然；
- 严格只用以下知识：[knowledge]；
- 不透露手机号/微信号之外的额外隐私；
- 访客语言决定回复语言（zh / en）；
- 不复制粘贴整段知识库原文，要咀嚼后表达。
```

## 八、风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 本地匹配器"答非所问"，显得不智能 | 体验 | 兜底要诚实（"这个我不确定"），绝不硬编；高频问题优先，FAQ 覆盖 30 条；UI 明确标注"本地知识库模式" |
| 纸面跨页与黑红背景衔接生硬 | 视觉割裂 | 撕纸 SVG + 胶带 + 火漆三件套；先做 1440/768/375 三档静态稿再写交互 |
| 纸面纹理性能差（噪点 SVG） | 卡顿 | 用 CSS 噪点 base64 + 静态图二选一；按 `prefers-reduced-motion` 关闭 |
| 双语知识库不一致 | 体验割裂 | `persona.js` 双字段同源；UI 文案走 V4 COPY |
| 人物立绘在纸面上白底突兀 | 视觉 | `mix-blend-mode: multiply` 融入纸面，避免硬切 |
| 未来接 LLM 时泄露 key | 安全 | 只走 Supabase Edge Function / Worker，key 放 secrets；推送前跑 `push-to-github` skill |
| V5 单文件体积过大（立绘 + 纹理） | 加载慢 | 立绘 WebP + 纹理 CSS 生成；总量控制 < 400KB |
